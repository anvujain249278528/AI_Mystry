# AI Mystery Room

AI Mystery Room is a full-stack detective game where each case is generated by Gemini and checked against a fixed, server-stored solution. Players investigate clues, interview suspects, request progressive hints, make one final accusation, and receive the complete explanation.

The project follows [spec.md](./spec.md). It uses React and Vite, Express and Node.js, MongoDB with Mongoose, and Google's official `@google/genai` SDK.

## Run locally

Requirements: Node.js 20 or newer, npm, a MongoDB connection, and a Gemini API key.

1. Copy `.env.example` to `.env` in the project root.
2. Set `MONGODB_URI` and `GEMINI_API_KEY` in `.env`. For a local MongoDB instance, the example URI is ready to use.
3. Install workspace dependencies and start both apps:

   ```sh
   npm install
   npm run dev
   ```

4. Open `http://localhost:5173`.

The API runs at `http://localhost:5000/api/v1`. The client gets its API base URL from `VITE_API_BASE_URL`. `CLIENT_URL` can contain a comma-separated list of permitted origins.

## API routes

All routes use `/api/v1`.

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/health` | API and database health |
| `POST` | `/mysteries/generate` | Generate a case and guest session |
| `GET` | `/mysteries/:id` | Retrieve player-visible case information |
| `GET` | `/games/:sessionId` | Retrieve the active investigation |
| `POST` | `/games/:sessionId/clues/:clueId/discover` | Search a hidden lead |
| `POST` | `/games/:sessionId/interrogate` | Ask a suspect a question |
| `POST` | `/games/:sessionId/hints` | Request the next hint level |
| `POST` | `/games/:sessionId/accusation` | Submit the one final accusation |
| `GET` | `/games/:sessionId/result` | Retrieve a completed result and solution |

Game routes require the `X-Session-Token` header returned by mystery generation. The token is only returned once and is stored in that browser profile's local investigation archive. The database stores its SHA-256 hash. The hidden solution and suspect-only knowledge are excluded from player-facing mystery responses.

## Environment variables

| Variable | Used by | Description |
| --- | --- | --- |
| `GEMINI_API_KEY` | Server | Gemini credential; never expose to the client |
| `GEMINI_MODEL` | Server | Model ID; defaults to `gemini-3.8-flash` |
| `MONGODB_URI` | Server | MongoDB connection string |
| `PORT` | Server | API port; defaults to `5000` |
| `CLIENT_URL` | Server | Allowed frontend origin(s) for CORS |
| `NODE_ENV` | Server | Runtime environment |
| `VITE_API_BASE_URL` | Client | API base URL; defaults to local API |

## Deployment

- **Frontend:** deploy the repository to Vercel. `vercel.json` builds `client` and rewrites browser routes to the SPA entry point. Set `VITE_API_BASE_URL` to the deployed API URL plus `/api/v1`.
- **Backend:** deploy the repository to Render using `render.yaml`. Set `GEMINI_API_KEY`, `MONGODB_URI`, and `CLIENT_URL` in the service environment.
- **Database:** use MongoDB Atlas for production and configure network access for the API host.

The backend exits during startup if MongoDB is not configured or cannot be reached. Gemini-dependent actions return a user-friendly configuration or availability error when the API key or service is unavailable; the game does not fall back to canned mysteries.

## Gameplay rules implemented

- Difficulty sets the suspect count and clue range; generated cases are validated before they are stored as playable.
- The culprit and solution are generated once and remain fixed for the case.
- Hidden clue details appear only after the player searches their location.
- Interrogation context excludes the solution. Hints use the fixed solution as server-side context and are requested in order.
- The backend locks a final accusation, checks the stored culprit ID, and calculates the score.
- Completed investigations and their results are stored in MongoDB.
